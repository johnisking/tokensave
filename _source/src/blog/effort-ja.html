Claude Opus 5.5 には、どれだけ深く考えるかを決める effort 設定が low、medium、high、xhigh、max の5段階あります。段階を上げるほど結果は良くなるとされていますが、時間と費用がどれだけ増えるのかは公式資料に数字がありません。そこで2026年10月9日、同じゲーム制作の依頼を5段階で1回ずつ実行し、時間、トークン、費用、出来上がったものを直接比べました。最も速い段階と最も遅い段階の差は32秒と22分でした。段階ごとに何が変わったのか、どの作業にどの段階を使えばよいのかを、実際に使ってきた感想とあわせてまとめました。

effort とは

  • 考える量を決める設定です。 Opus 5.5 は thinking をオフにできず、effort でどれだけ深く考えるかを調整します。考えたトークンにも出力トークンとして料金がかかります。
  • 既定値は medium です。 Opus 5 は high が既定でしたが、Opus 5.5 は1段階低い medium が既定です（Anthropic のドキュメントより）。
  • 変え方： Claude Code では --effort オプションで low から max まで選べ、API では effort の値を指定します。

計測方法

  • モデル： Claude Opus 5.5、Claude Code（Windows PC）
  • 依頼（原文のまま）： "Make a brick-breaker game that runs in the browser as a single file named index.html in the current folder. It needs 2 levels, a score display and 3 lives, and it must be playable with the keyboard and the mouse. Write the file and finish." ブラウザで動くブロック崩しを HTML ファイル1つで、2レベル、スコア、ライフ3つ、キーボード・マウス操作で作るという内容です。
  • 方法： 同じ依頼を effort だけ変えて5回実行しました。段階ごとに別のフォルダを使い、互いに影響しないようにしました。
  • 計測： トークンと費用は無料ツール ccusage で、時間は開始・終了時刻で測りました。費用は API 料金に換算した値です。

計測結果：時間・トークン・費用

effort かかった時間 出力トークン 合計トークン 費用 ゲームのコード
low 32秒 3,368 129,315 $0.48 138行
medium（既定） 52秒 6,299 133,428 $0.56 358行
high 1分50秒 12,376 222,854 $0.75 523行
xhigh 4分32秒 32,435 472,082 $1.36 639行
max 22分22秒 160,033 2,504,957 $5.25 1,121行
  • low と medium はほとんど差がありません。 low は費用が14%、時間が38%少なかったものの、金額では8セントの差です。
  • high は medium より費用が34%増えただけでした。 時間は52秒から1分50秒に延びました。
  • xhigh から大きく増えます。 費用は medium より143%多く、時間は4分32秒です。
  • max は別格です。 medium が52秒・$0.56のところ、max は22分22秒・$5.25でした。出力トークンも6,299から160,033に増えました。

出来上がったもの：5つのゲーム画面

5つのゲームはすべてエラーなく動き、2レベル、スコア、ライフ3つ、キーボード・マウス操作という依頼はすべて満たしていました。違いは、その上に足された機能と見た目です。

effort 追加されたもの
low 単色のブロック、最もシンプルな画面、一時停止なし
medium 虹色のブロック、一時停止、リスタート
high ＋パーティクル効果、ベストスコアの保存
xhigh パーティクル効果、より洗練されたデザイン（ベストスコア保存はなし）
max ＋効果音、レベル名、インベーダー型のレベル2、画面の揺れ、勝利の花火
  • high 以上は自分で確認しようとしました。 high と xhigh はコードの構文チェックを、max はゲームを自動でプレイするテストを試みました。どれも実行に承認が必要で実際には動かせず、コードを読み直して確認したと書いています。low と medium は確認せずにすぐ終えました。
  • 2回当てないと壊れないブロックは、依頼していないのに全段階が入れていました。

段階別の詳しいレビュー

それぞれのゲームを実際に遊び、モデルが作業の最後に残した説明とコードもあわせて確認しました。

low：32秒、$0.48

  • 作ったもの： レベル1は青いブロック4段、レベル2は2回当てると壊れるオレンジのブロックと空きが混ざり、ボールが速くなります。レベルクリア・ゲームオーバー・勝利画面とリスタートはあります。
  • 良かった点： 依頼した機能は漏れなく入っていて、パドルのどこに当たるかでボールの角度が変わります。32秒で終わりました。
  • 惜しい点： 黒い背景に単色のブロックで最も地味です。一時停止がなく、コードも138行で最短です。
  • 向いている場面： 動くかどうかだけ早く確かめ、デザインは後で整えるとき。

medium：52秒、$0.56（既定値）

  • 作ったもの： レベル1は5×10の虹色のブロック、レベル2は空きのある配置に2〜3回当てると壊れるブロックが混ざります。残り回数がブロックに表示され、当たるほど薄くなります。
  • 良かった点： 一時停止（P・Esc）、リスタート（Enter）、ウィンドウを離れると自動で一時停止する機能まで入っています。スコアもブロックの耐久とレベルで変わります。
  • 惜しい点： 効果音やパーティクルのような演出はありません。
  • 向いている場面： ほとんどの作業。low より8セント高いだけで、完成度は一段上です。

high：1分50秒、$0.75

  • 作ったもの： レベル2はダイヤ型の配置に2〜3回当てると壊れるブロック。ブロックが壊れるとパーティクルが飛びます。
  • 良かった点： レベルクリアのボーナス、残りライフのボーナス、ベストスコアの保存まであり、タッチ操作にも対応しています。自分で構文チェックも試みました。
  • 惜しい点： 時間は medium より112%長くかかりました（52秒 → 1分50秒）。
  • 向いている場面： すぐ人に見せるプロトタイプや、完成度が大事なコーディング。費用は medium より34%増えただけです。

xhigh：4分32秒、$1.36

  • 作ったもの： レベル2はダイヤ型で、周りを鋼鉄のブロックが囲み、1回当たるとひびが入ります。ブロックの色ごとに10〜50点と点数が違います。
  • 良かった点： 画面が最も整って見え、マウスとキーボードを混ぜて使っても、最後に使った方で自然に動きます。
  • 惜しい点： high にあったベストスコアの保存とタッチ操作がなくなりました。費用は medium より143%多いのに、high と比べて機能は増えていません。
  • 向いている場面： 今回のような小さな作業には過剰です。Anthropic の案内どおり、長時間かかる大きな作業向けです。

max：22分22秒、$5.25

  • 作ったもの： レベル名（"Rainbow Wall"、"Space Invader"）、インベーダー型のレベル2（銀色のブロック14個は2回当てると壊れる）、レベル2で細くなるパドル。
  • 良かった点： 効果音（M でオン・オフ）、ベストスコアの保存、タッチ操作、画面の揺れ、勝利の花火、ウィンドウを離れると自動で一時停止まで、5つの中で最も多くを入れました。そのままゲームとして見えます。
  • 惜しい点： ほかの段階よりはるかに長くかかりました。承認が必要で実行できなかった自動プレイテストの試みも含まれています。
  • 向いている場面： 品質が最優先で時間と上限に余裕があるとき、またはほかの段階で解けない問題。

使ってみた感想：普段は medium、コーディングは high

私は Claude Max 20x プランでゲームを作りながら Opus 5.5 を使っています。測定値ではなく、普段使って感じたことです。

  • 普段の設定： effort は自動（auto）にしています。普段は medium で動き、コーディングのときは high まで上がります。
  • low： もどかしく感じて、何度か使ってやめました。
  • high： 明らかに結果が良いと感じました。
  • xhigh・max： 1回使ったくらいで、使う場面がほとんどないので使っていません。

計測と比べると、low は速度は最も速かったものの、出来上がりが最もシンプルでした。「もどかしい」という感覚は、速度より出来上がりのほうだったわけです。high で結果が良くなる感覚と、xhigh・max を使う場面がない感覚は、数字とも一致しました。

Anthropic の案内

  • medium も十分に強力です。 Anthropic のテストでは、Opus 5.5 の medium はコーディングと知識作業で Opus 5 の high と同等以上でした。
  • low もコーディングでは medium に近いとしています。 費用はずっと少ないとのことです。ただ、今回の計測では出来上がりの差がはっきり出ました。
  • xhigh と max は、品質向上を確認できた作業にだけ使うよう勧めています。
  • 途中で effort を変えるとキャッシュが無効になることがあります。 API ではメッセージ単位で変える方法を使えばキャッシュが保たれます。
  • 独立評価も同じ傾向です。 Artificial Analysis は、最高設定の Opus 5.5 が1タスクあたりの出力トークンを Opus 5 より63%多く使ったとしています（報道ベース）。

どの作業にどの effort を使うか

計測、私の経験、Anthropic の案内をまとめたおすすめです。

作業 おすすめ effort 理由
文言の修正、ファイル整理などの簡単な作業 low または medium 速くて安いが、low は出来がシンプル
普段のコーディング、機能追加など大半の作業 medium（既定） 52秒・$0.56で使える結果
ゲーム・アプリのプロトタイプ、完成度が必要なコーディング high 費用34%増で出来が明らかに良くなる
30分以上かかる長い作業、大きなリファクタリング xhigh Anthropic の案内より
ほかの段階で解けない難しい問題 max 時間と費用が大きく増えるので必要なときだけ
  • まずは medium から始めましょう。 結果が物足りない作業だけ high に上げれば十分です。
  • プランの利用者は上限で考えましょう。 API 換算の費用が大きいほど Max・Pro の上限も早く減ります。max 1回で medium 9回分以上を使いました。
  • 注意： 段階ごとに1回ずつ、比較的小さな作業で測った結果です。大きなプロジェクトでは差が変わる可能性があります。

結論：普段は medium、しっかり作るなら high

  • 普段：medium。 52秒・$0.56で使える結果が出ます。
  • 完成度が必要なとき：high。 費用は medium より34%増えるだけで、出来は明らかに良くなりました。最もコスパの良い段階です。
  • xhigh：小さな作業にはおすすめしません。 費用は medium より143%多いのに、high より機能は増えませんでした。30分以上かかる大きな作業向けです。
  • max：本当に必要なときだけ。 出来は最も派手ですが、22分・$5.25かかりました。
  • low：おすすめしません。 medium より8セント節約しても、出来がシンプルになるだけです。

よくある質問

Opus 5.5 の既定の effort は？ medium です。Opus 5 は high が既定でした。API で effort を指定しない場合、Opus 5.5 は medium で動きます。

max にすれば必ず良くなりますか？ 今回の計測では機能と演出が最も多かったものの、時間は22分、費用は$5.25で、medium（52秒・$0.56）との差が大きくなりました。簡単な作業には過剰です。

low にすると大きく節約できますか？ 今回の計測では、low は medium より14%安いだけでした。出来がシンプルになることを考えると、medium のほうが良い選択です。
