# Blender MCPのトークンを実測：Claude Codeで72回、レーシングシーン1本は約74円（$0.47）

BlenderをMCPでClaudeにつなぐとトークンを大量に使う、という話を聞きます。ところが実測した記事が見つからなかったので、いちばん使われている「MCP for Blender」をClaude Codeで72回動かして測りました。シーンの説明、家具づくり、色を変えてスクリーンショットで確認、最悪のケース2つ、そしてショーケースとしてチェイスカメラ付きのレーシングシーンです。ブラウザMCP用に作った削減プロキシ（バージョン0.3）を通した場合も同じタスクで測りました。

## 測り方

- Claude Code 2.1.295、Opus 5.5、effort medium、Windows 11、GTX 1650（2026-10-22）
- Blender 5.2.2 LTS、MCP for Blender（`uvx mcp-for-blender`、アドオン1.8、テレメトリーはオフ）
- つないだMCPサーバーはBlenderだけ。Web・ファイル・シェルなどの標準ツールと、サーバーの3D生成・アセットダウンロードのツールは無効
- シーンは自作スクリプトで毎回同じものを用意：オブジェクト13個の部屋、580個の街区、空のシーン
- 実行後に保存した.blendファイルを読み、テーブルと椅子4脚があるか、椅子が本当に赤いか、120フレームのアニメーションか、カメラが車を追うかを確認。72回すべて合格

## 結果1：普段の作業は1回$0.16〜0.23（約25〜36円）

| タスク（各5回） | 入力トークン | 費用 |
|---|---:|---:|
| 小さな部屋を説明 | 69,606 | $0.16 |
| 580個の街区を説明 | 115,868 | $0.19 |
| ローポリのテーブルと椅子4脚を作る | 125,563 | $0.23 |
| 椅子を赤くしてスクリーンショットで確認 | 124,649 | $0.20 |
| テーブルを4方向から見る | 112,118 | $0.21 |

（費用はOpus 5.5のAPI価格、Claude Codeの報告値）

この25回でツールが返した最大のテキストは2,347文字でした。今のMCP for Blenderはすでに軽く作られていて、シーン情報は1回20オブジェクトまで、スクリーンショットは768ピクセルが既定です。1リクエストの大半（約2万5千トークン）はClaude Code自身の指示文で、手順のたびに繰り返し送られます。

## 結果3：高くつくのは長いスクリプト出力

580個すべてのオブジェクトのプロパティを出力させると、スクリプトの出力は122,373文字になりました。Claude Codeは大きすぎるとして受け取らず、Claudeは約3万2千文字ずつ4回に分けて出し直し、その4回分がすべてコンテキストに残りました。

- 入力242,782トークン、1回$0.87。普段の作業の4倍以上

球の頂点19,042個をすべて出力させた場合は、Claude Codeが拒否したあと、Claudeが「出力した」と報告して終わったため$0.17で済みました。

## 削減プロキシ tokensave-mcp-diet 0.3

サーバーの前に挟む中継サーバーで、ツールはすべてそのまま通します。Blenderでは次の2つを行います。

1. **長いテキスト結果**（8,000文字超）は先頭2,000文字と末尾1,000文字を残し、隠した部分を要約します。プロパティ出力では「568行（132,418文字）を省略…568行が `name=Building ## | type=MESH | location=(#, #, #) ...` の形」と表示されました。全文はメモリに残り、新しいツール `result_detail` で行番号や検索で必要な部分を読めます。
2. **画像を小さく**：`max_size` を持つツールは、モデルが1,000ピクセル超を明示しない限り512ピクセルにします。

設定：

```json
{
  "mcpServers": {
    "blender": {
      "command": "npx",
      "args": ["-y", "github:johnisking/tokensave-mcp-diet", "--", "uvx", "mcp-for-blender"]
    }
  }
}
```

| タスク | そのまま | プロキシあり | 変化 |
|---|---:|---:|---:|
| 580個のプロパティを全部出力（3回） | $0.873 | $0.166 | −81% |
| レーシングシーン（5回） | $0.471 | $0.445 | −6% |
| 普段の作業（各5回） | $0.16〜0.23 | $0.15〜0.21 | −4%〜−8% |

正直に書くと、レーシングシーンでは画像トークンが62%減りましたが、画像は入力全体のごく一部なので費用は6%しか下がらず、これは実行ごとのばらつきの範囲です。プロキシが何も変えていない「小さな部屋の説明」でも4%安く出ているので、普段の作業の差はノイズと見るべきです。このプロキシはすべてを安くするものではなく、長い出力が出たときの安全装置です。

途中で見つけたバグ：MCP for Blenderは結果を `structuredContent` でも返し、Claude Codeはテキストではなくそちらを表示するため、最初の計測では長い出力がまったく短くなっていませんでした。0.3ではそちらも短くするよう直し、該当タスクは修正後に測り直しました。

## 実際に使うときのポイント

- 普段の作業ではBlender MCPはトークンを大量に使いません。費用は手順の数で決まり、1手順の大半はClaude Code自身の分です。
- 大量に出力するスクリプトに注意。プロパティを1回全部出しただけで、普段の作業4回分以上かかりました。「全部出して」ではなく、件数や要約、ファイル出力を頼みましょう。
- 大きなツール結果をそのまま受け取るクライアントでは、同じ出力が一度にコンテキストへ入ります。こうしたプロキシがいちばん役立つのはその場面です。

## 今回の限界

- モデル1つ、PC1台、クライアント1つ。各タスク5回（最悪ケース2つは3回）
- Claudeが毎回違う手順で進むため、費用は実行ごとにばらつきます
- 画像トークンは画像サイズからの推定（幅×高さ÷750）。入力トークンの合計は実測値です
- MCP for Blenderは更新が速く、これは2026年10月版の結果です
