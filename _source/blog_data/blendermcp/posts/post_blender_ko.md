# 블렌더 MCP는 토큰을 얼마나 먹을까? Claude Code로 72번 실측, 레이싱 장면 하나에 $0.47

블렌더를 MCP로 Claude에 붙이면 토큰이 엄청 든다는 말을 자주 듣습니다. 그런데 실제로 잰 자료는 하나도 찾을 수 없어서, 가장 많이 쓰이는 "MCP for Blender"를 Claude Code로 72번 돌려 직접 쟀습니다. 장면 설명, 가구 만들기, 색 바꾸고 화면으로 확인하기, 최악의 경우 2가지, 그리고 보여 주기용으로 추격 카메라가 달린 레이싱 장면까지입니다. 브라우저 MCP 때 만든 토큰 다이어트 도구(0.3 버전)를 끼운 경우도 같은 과제로 쟀습니다.

## 어떻게 쟀나

- Claude Code 2.1.295, 오퍼스 5.5, effort medium, Windows 11, GTX 1650 (2026-10-22)
- 블렌더 5.2.2 LTS, MCP for Blender (`uvx mcp-for-blender`, 애드온 1.8, 데이터 수집 꺼짐)
- 블렌더 MCP만 붙이고, 웹·파일·셸 같은 기본 도구와 서버의 3D 생성·에셋 다운로드 도구는 껐습니다
- 장면은 직접 만든 스크립트로 매번 똑같이 준비했습니다: 물체 13개짜리 방, 580개짜리 도시 블록, 빈 장면
- 실행이 끝나면 저장된 .blend 파일을 열어 탁자와 의자 4개가 있는지, 의자가 정말 빨간지, 애니메이션이 120프레임인지, 카메라가 차를 따라가는지 확인했습니다. 72번 모두 통과했습니다.

이 25번 동안 도구가 돌려준 가장 큰 글도 2,347자였습니다. 지금 MCP for Blender는 이미 가볍게 만들어져 있어서 장면 정보는 한 번에 물체 20개까지, 화면 캡처는 768픽셀이 기본입니다. 요청 하나에 실리는 토큰(약 2만 5천)의 대부분은 Claude Code 자체의 지시문이고, 단계마다 다시 실립니다.

## 결과 3: 비싼 경우는 긴 출력 하나뿐

구체의 정점 19,042개를 전부 출력하게 한 경우는 Claude Code가 거부한 뒤 Claude가 "출력했다"고 보고하고 끝나서 $0.17로 끝났습니다.

## 다이어트 도구: tokensave-mcp-diet 0.3

블렌더 MCP 앞에 끼워 쓰는 중간 다리이고, 모든 도구는 그대로 통과시킵니다. 블렌더에서는 두 가지를 합니다.

1. **긴 글 결과**(8,000자 초과)는 앞 2,000자와 뒤 1,000자만 남기고 가운데를 요약합니다. 속성 출력에서는 "568줄(132,418자) 생략… 568줄이 `name=Building ## | type=MESH | location=(#, #, #) ...` 모양"이라고 나왔습니다. 전체 글은 보관해 두고, 새 도구 `result_detail`로 줄 번호나 검색어로 필요한 부분만 꺼내 읽게 합니다.
2. **이미지는 작게**: `max_size`가 있는 도구는 모델이 1,000픽셀 넘게 달라고 하지 않는 한 512픽셀로 받습니다.

설정:

```json
{
  "mcpServers": {
    "blender": {
      "command": "npx",
      "args": ["-y", "github:johnisking/tokensave-mcp-diet", "--", "uvx", "mcp-for-blender"]
    }
  }
}
```

| 과제 | 그대로 | 다이어트 | 변화 |
|---|---:|---:|---:|
| 물체 580개 속성 전부 출력 (3회) | $0.873 | $0.166 | −81% |
| 레이싱 장면 (5회) | $0.471 | $0.445 | −6% |
| 평소 작업 (각 5회) | $0.16~0.23 | $0.15~0.21 | −4%~−8% |

정직하게 말하면, 레이싱 장면에서 이미지 토큰은 62% 줄었지만 이미지가 전체 입력에서 차지하는 몫이 작아서 비용은 6%만 줄었고, 이건 실행마다 생기는 편차 범위 안입니다. 다이어트가 아무것도 바꾸지 않은 "작은 방 설명"도 4% 싸게 나왔으니, 평소 작업의 차이는 오차로 봐야 합니다. 이 도구는 모든 걸 싸게 해 주는 게 아니라, 긴 출력이 터졌을 때의 안전장치입니다.

측정 중 발견한 버그도 있습니다. MCP for Blender는 결과를 `structuredContent`로도 보내는데, Claude Code는 글 대신 그쪽을 보여 줘서 처음 측정에서는 긴 출력이 전혀 줄지 않았습니다. 0.3에서 그쪽도 줄이게 고쳤고, 해당 과제는 고친 뒤 다시 쟀습니다.

## 실제로 쓸 때 기억할 것

- 평소 작업에서 블렌더 MCP는 토큰을 크게 먹지 않습니다. 비용은 단계 수에 따라 정해지고, 한 단계의 대부분은 Claude Code 자신의 몫입니다.
- 많이 출력하는 스크립트를 조심하세요. 속성 한 번 전부 뽑는 데 평소 작업 4번어치가 들었습니다. "전부 출력해" 대신 개수나 요약, 파일 저장을 부탁하는 게 낫습니다.
- 큰 도구 결과를 그대로 받는 프로그램을 쓴다면 같은 출력이 한 번에 통째로 들어옵니다. 이런 다이어트 도구가 가장 쓸모 있는 곳이 거기입니다.

## 한계
