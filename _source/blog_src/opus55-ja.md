![Claude Opus 5 と 5.5 の違い：料金・性能・実測レビュー](/claude-opus-5-vs-5-5-ja.jpg)

Claude **Opus 5.5** は、2026年9月22日に登場した Anthropic の新しい上位モデルです。前のモデル **Opus 5** と比べて、トークン単価は20%安く、キャッシュ読み取りは60%安くなりました。Anthropic は「一般的な作業で運用コストが40%少ない」としていますが、コーディングエージェントの作業で私たちが計算すると約37%安くなりました。同じゲーム制作の依頼で実際に測ると、Opus 5.5 のトークン使用量は64%少なくなりました。料金・性能・実測結果を比べ、Max 20x プランで両モデルを使った感想とあわせて、乗り換える価値があるかをまとめました。

## Opus 5 と 5.5 の料金比較

![Opus 5 と 5.5 の料金比較: 項目, Opus 5, Opus 5.5, 差](/claude-opus-5-vs-5-5-opus-5-5-5-ja.jpg)

Anthropic の公式料金ページより、100万トークンあたりの価格です。

| 項目 | Opus 5 | Opus 5.5 | 差 |
|---|---:|---:|---:|
| 入力 | $5 | $4 | 20%安い |
| 出力 | $25 | $20 | 20%安い |
| キャッシュ書き込み（5分） | $6.25 | $5 | 20%安い |
| キャッシュ読み取り | $0.50 | $0.20 | **60%安い** |
| 高速モード | – | $8 / $40 | Opus 5.5 で追加 |

- **キャッシュ読み取りが最も大きく下がりました。** Opus 5 では入力価格の10%でしたが、Opus 5.5 では5%です。同じ文書や会話を繰り返し読む作業ほど差が大きくなります。
- **同じ文章ならトークン数は同じです。** どちらも Claude 4.7 以降の新しいトークナイザーを使うため、同じ文章を入れればトークン数は同じで、単価の差がそのまま費用の差になります。ただし、作業中にモデルが使うトークン量は変わることがあります（下の実測を参照）。
- **高速モード：** Opus 5.5 には入力 $8、出力 $40 の高速モードが加わりました。Claude Code と API で使え、Anthropic によると速度は最大150%速くなります。

## 使ってみた感想：Max 20x の週間上限が余るようになった

私は Claude Max 20x プランでゲームを作りながら、Opus 5 と Opus 5.5 の両方を使いました。測定した数値ではなく、実際に使って感じたことです。

- **週間上限：** Opus 5 のときは、週間上限がリセットされる1日前に使い切るくらいでした。Opus 5.5 に変えてからは、1週間を使用量90%ほどで終えることが多くなりました。
- **外部作業：** トークンを多く使う外部作業を任せたときに差が一番大きく出ました。使ったモデルの中で、Opus 5.5 がいちばんトークンを使わない印象でした。
- **コーディング性能とコスパ：** コーディングでは Fable 5.1 並みの性能が出る感覚で、コスパはずっと良く感じました。参考までに、API 単価は Opus 5.5（入力 $4、出力 $20）が Fable 5.1（入力 $10、出力 $50）より60%安くなっています。

上の公式料金と下の計算結果も同じ方向です。同じ作業をより少ない費用（＝より少ない上限）でこなすので、同じプランでより長く使えます。

## 同じ依頼で実際に測ってみた

![同じ依頼で実測：Opus 5 と Opus 5.5 が作ったブロック崩しゲームの比較](/claude-opus-5-vs-5-5-ja-5.jpg)

感覚だけでは足りないので、2026年10月9日に Claude Code で両モデルに**同じ依頼**を1回ずつ出しました（モデル名だけを変え、ほかの設定はそのまま）。ブラウザで動くブロック崩しゲーム（2レベル、スコアとライフ表示）を HTML ファイル1つで作るという依頼で、使用量は無料ツール ccusage で測りました。

| 項目 | Opus 5 | Opus 5.5 | 差 |
|---|---:|---:|---:|
| 出力トークン | 36,640 | 15,180 | 59%少ない |
| キャッシュ書き込みトークン | 74,533 | 63,917 | 14%少ない |
| キャッシュ読み取りトークン | 1,774,025 | 595,337 | 66%少ない |
| 合計トークン | 1,885,246 | 674,452 | **64%少ない** |
| 費用（API 料金換算） | $2.55 | $0.93 | **64%安い** |
| 作ったゲームのコード | 約684行 | 409行 | 40%短い |

![同じ依頼で使ったトークンのグラフ：Opus 5 は188万、Opus 5.5 は67万トークン](/claude-opus-5-vs-5-5-ja-6.jpg)

- **費用の差は単価の差（20%）よりずっと大きくなりました。** Opus 5.5 は同じ依頼を処理しながら、トークンそのものを64%少なく使いました。特に前の会話を読み直すキャッシュ読み取りが66%減りました。Max プランで週間上限が余るようになった理由と同じ方向です。
- **機能は Opus 5 のほうが多くありました。** 2回当てないと壊れないブロックは両方にありましたが（Opus 5.5 はレベル2から）、Opus 5 にはパーティクル効果、いつでもリスタートできる R キー、レベルクリアのボーナス、ブロックに残り耐久の数字表示もありました。ただ、画面は私の目には Opus 5.5 のほうがすっきりして見やすく感じました。トークンが少なかったのには、この機能の差も一部関係しています。
- **Opus 5.5 のファイルは末尾が欠けていました。** 最後の閉じタグ（`</script></body></html>`）がなく、最初は真っ白な画面でした。その3つを足すと正常に遊べました。Opus 5 のファイルはそのまま動きました。
- **注意：** 各モデル1回ずつの結果なので、やり直すと数字が変わる可能性があります。費用は ccusage が API 料金で換算した値で、プランの利用者はこの金額を払うのではなく上限から差し引かれます。

![ccusage の実測記録：2026年10月9日の Opus 5 と Opus 5.5 のトークンと費用](/claude-opus-5-vs-5-5-ja-7.jpg)

## 実際の作業費用の比較

![実際の作業費用の比較: 作業, Opus 5, Opus 5.5, 差](/claude-opus-5-vs-5-5-ja-3.jpg)

同じ作業を両モデルで実行した場合の費用を計算しました。トークン数は同じとして、価格だけを変えています。

| 作業 | Opus 5 | Opus 5.5 | 差 |
|---|---:|---:|---:|
| チャット1回（入力2,000 / 出力500） | $0.0225 | $0.018 | 20%安い |
| 文書への質問1回（入力5万のうち4万5,000がキャッシュ / 出力1,000） | $0.0725 | $0.049 | 32%安い |
| コーディングエージェントで機能1つ（入力160万、大半がキャッシュ / 出力1万7,500） | $1.79 | $1.14 | 37%安い |
| コーディングエージェント1か月（機能110個） | 約 $197 | 約 $125 | 37%安い |

計算例：Opus 5.5 の文書への質問 = 新しい入力5,000 × $4 + キャッシュ45,000 × $0.20 + 出力1,000 × $20（すべて100万トークンあたり）= $0.049。

**キャッシュを多く使うほど節約幅が大きくなります。** 単純なチャットは20%しか安くなりませんが、会話を読み直し続けるコーディングエージェントは37%近く安くなります。この表はトークン数を同じとした計算です。Anthropic は「40%削減」が、既定の設定で単価の値下げと**作業あたりのトークン減少**を合わせた結果だとしており、上の実測でもトークンは64%減りました。

## 性能比較（Anthropic の発表より）

![性能比較（Anthropic の発表より）：Opus 5 と Opus 5.5 のベンチマーク棒グラフ](/claude-opus-5-vs-5-5-ja-4.jpg)

Anthropic が公開したベンチマークです。Opus 5.5 のスコアは最高設定（max effort）で、Terminal-Bench 4.0 だけは1段階下（xhigh）です。すべて Anthropic 自身による測定です。

| ベンチマーク | Opus 5 | Opus 5.5 |
|---|---:|---:|
| Terminal-Bench 4.0（ターミナル作業） | 52.3% | 66.4% |
| CursorBench 4.0（コーディング） | 46.6% | 57.8% |
| FrontierCode v1.1（コーディング） | 48.0% | 54.4% |
| AutomationBench（業務自動化） | 26.9% | 40.0% |
| OSWorld 2.1（コンピューター操作、一部） | 74.0% | 81.8% |
| Humanity's Last Exam（ツール使用） | 63.6% | 67.7% |

- **コーディングとエージェント作業で差が大きくなっています。** ターミナル作業は14.1ポイント、業務自動化は13.1ポイント上がりました。
- **速度：** Anthropic によると、出力の生成速度は Opus 5 より30%以上速くなっています。
- **注意：** 会社自身が測ったスコアなので、自分の作業でも同じ差が出るかは試してみる必要があります。

## 独立評価：Artificial Analysis

会社の外で測ったスコアもあります。独立評価機関 Artificial Analysis の総合指標 Intelligence Index で、Opus 5.5（最高設定）は58点で1位になりました（報道ベース）。

| モデル | Intelligence Index |
|---|---:|
| Claude Opus 5.5（max effort） | 58 |
| GPT-6 Astra | 53 |
| Claude Fable 5.1 | 53 |
| Claude Opus 5 | 51 |

- **独立評価でも Opus 5.5 が上回りました。** Opus 5 より7点高い結果です。
- **ただしトークンは多く使いました。** 同じ評価で1タスクあたりの出力トークンは、Opus 5.5（最高設定）が約11万9,000、Opus 5 が約7万3,000で、Opus 5.5 が63%多くなりました。理由はすぐ下で説明します。

## effort 設定で節約幅が変わる

- **既定の設定が変わりました。** Anthropic の移行ガイドによると、effort を指定しない場合、Opus 5 は high、Opus 5.5 は medium で動きます。「40%削減」はこの既定設定でのものです。
- **最高設定では節約がなくなることがあります。** Artificial Analysis は、最高設定の Opus 5.5 が出力トークンを63%多く使い、1タスクあたりの費用は Opus 5 とほぼ同じだったとしています（報道ベース）。
- **私たちの実測は逆の結果でした。** Claude Code でモデル名だけを変えて実行すると、Opus 5.5 のトークンは64%少なくなりました。設定と作業によって結果が大きく変わるということです。
- **おすすめ：** medium から始め、品質が足りない作業だけ high 以上に上げましょう。xhigh・max を使うときは、Anthropic の案内どおり max_tokens を大きめ（64k から）に設定してください。
- **段階別の実測：** low から max まで同じ依頼で測った結果は [Claude Opus 5.5 の effort 比較](/ja/blog/claude-opus-5-5-effort) にまとめました。
- **Sonnet 5.5 との比較：** 同じ依頼を Sonnet 5.5 で実行した結果は [Claude Sonnet 5.5 vs Opus 5.5](/ja/blog/claude-sonnet-5-5-vs-opus-5-5) にまとめました。

## Pro・Max プランの利用者には

- サブスクリプションでは、トークン単価ではなく**上限**が重要です。Anthropic は Opus 5.5 の公開に合わせて、Pro、Max、Team、シート制 Enterprise の5時間の使用上限を引き上げ、あとで使える上限リセットも提供するとしています。
- 同じ作業をより少ない費用でこなすモデルなので、同じ上限の中でより多く使える可能性が高いです。ただし、Anthropic はプランごとの正確な上限を公開していません。

## 長所と短所

![Opus 5.5 の長所と短所のまとめカード](/claude-opus-5-vs-5-5-ja-9.jpg)

**長所**

- **より安く、より高性能：** トークン単価20%、キャッシュ読み取り60%の値下げに加え、ベンチマークのスコアも上がりました。
- **エージェント作業に特に有利：** キャッシュを多く使うコーディングや自動化の作業で、費用が約37%下がります。
- **高速モードを選べる：** 急ぐときは費用を多めに払って速度を上げられます。

**短所**

- **依然として高いモデル：** Sonnet 5.5（入力 $2、出力 $10）よりトークンあたり100%高くなります。簡単な作業なら Sonnet で十分です。
- **性能の数値の多くは会社の発表：** 独立評価（Artificial Analysis）でも1位でしたが、自分の作業で確認が必要です。
- **最高設定では節約幅が縮む：** 長く考えるため、出力トークンが増えます。
- **高速モードは高い：** 通常モードより100%高くなります。

## API の移行で変えるべきこと

Anthropic の移行ガイドによると、Opus 5 向けのコードをそのまま使うとエラー（400）になる部分があります。

| 変更点 | Opus 5.5 でやること |
|---|---|
| thinking をオフにできない：`disabled`、`budget_tokens` はエラー | thinking の設定を外し、effort で調整 |
| ツールの強制呼び出し不可：`tool_choice` の `any`・`tool` はエラー | `auto` と strict ツール、または構造化出力 |
| 古いコンピューター操作ツール（`computer_20251124`）は API・Google Cloud でエラー | `computer_toolset_20260801` に変更 |
| 途中の会話を編集したあと thinking ブロックを送り直すとエラー（2026年8月31日以降に作成したアカウント） | 会話履歴は後ろに追加するだけにする |
| ツール呼び出しの間の説明文が thinking ブロックに移動 | 画面に表示するなら `thinking.display` を設定 |
| 拒否（`stop_reason: "refusal"`）の範囲が拡大 | 拒否の処理と代替モデルを設定 |

このほか、Priority Tier は Opus 5.5 では使えません。Claude Code やプランで使う場合、自分で直すコードはありません。

## Opus 5 から乗り換えるべきか

- **API で Opus 5 を使っているなら：** 乗り換えをおすすめします。費用は20〜37%下がり、性能は上がります。ただし、モデル名を変えるだけでは済みません。上の変更点を直し、effort を明示して、まず開発環境で試してください。
- **Claude Code で大きな作業をよく回すなら：** キャッシュ割引の効果が最も大きいケースなので、得るものが大きいです。
- **Sonnet で足りる作業なら：** Opus 5.5 に上げる必要はありません。難しい設計やデバッグだけを Opus に任せるのが最も経済的です。

## よくある質問

**Opus 5.5 は Opus 5 よりどれくらい安いですか？**
トークン単価は20%、キャッシュ読み取りは60%安くなります。実際の作業費用では、チャットで20%、キャッシュを多く使うコーディングエージェント作業で約37%安くなります。

**トークン数も変わりますか？**
同じ文章を入れればトークン数は同じです（同じトークナイザー）。ただし作業で使うトークンは違います。私たちの実測では Opus 5.5 が64%少なく、最高設定では逆に多く使うこともあります。

**Opus 5.5 と Sonnet 5.5 のどちらを使うべきですか？**
ほとんどの作業は Sonnet 5.5 で十分で、トークンあたりの価格も半分です。難しいコーディング、長いエージェント作業、品質が重要な文章には Opus 5.5 を使いましょう。

**Opus 5 向けの API コードをそのまま使えますか？**
いいえ。thinking のオフや `tool_choice` による強制呼び出しなどは、Opus 5.5 ではエラーになります。上の「API の移行で変えるべきこと」を確認してください。
