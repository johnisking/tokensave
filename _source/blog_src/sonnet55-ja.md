## 計測方法

- **環境：** Opus 5.5 の effort 実測と同じ Windows PC、同じ Claude Code
- **依頼（原文のまま）：** "Make a brick-breaker game that runs in the browser as a single file named index.html in the current folder. It needs 2 levels, a score display and 3 lives, and it must be playable with the keyboard and the mouse. Write the file and finish." ブラウザで動くブロック崩しを HTML ファイル1つで、2レベル、スコア、ライフ3つ、キーボード・マウス操作で作るという内容です。
- **方法：** Sonnet 5.5 を `--effort medium` と `--effort high` で1回ずつ実行し、同じ日に測った Opus 5.5 の medium・high の結果と比べました。段階ごとに別のフォルダを使いました。
- **計測：** トークンと費用は無料ツール ccusage で、時間は開始・終了時刻で測りました。費用は API 料金に換算した値です。

## 4つのゲームを比較

![Sonnet 5.5 と Opus 5.5 が medium・high で作ったブロック崩し4つの比較](/claude-sonnet-5-5-vs-opus-5-5-ja-5.jpg)

4つとも問題なく動き、依頼した機能（2レベル、スコア、ライフ3つ、キーボード・マウス操作）をすべて備えていました。違いは、その上に何を足したかです。

| モデル · effort | 追加したもの |
|---|---|
| Sonnet medium | 虹色のブロック、レベル2の市松模様の配置と2回当てないと壊れない最上段、一時停止 |
| Opus medium | 虹色のブロック、2〜3回当てないと壊れないブロック（残り回数を表示）、一時停止・リスタート、ウィンドウを離れると自動停止 |
| Sonnet high | パーティクル効果、ハイスコア保存、レベルクリアボーナス、レベル2で狭くなるパドルと速くなるボール、自動停止 |
| Opus high | パーティクル効果、ハイスコア保存、クリア・残りライフのボーナス、タッチ操作 |

- **Sonnet high は Opus high とほぼ同じ機能構成でした。** 足りなかったのはタッチ操作くらいです。
- **Sonnet medium が最もシンプルでした。** 効果音やパーティクルといった飾りがありません。

## 段階ごとの詳しいレビュー

ゲームを実際に遊び、モデルが最後に残した要約とコードもあわせて確認しました。Opus 5.5 の medium・high のレビューは [effort 比較の記事](/ja/blog/claude-opus-5-5-effort) にあります。

### Sonnet 5.5 medium：37秒、$0.25

- **作ったもの：** レベル1は5段のブロック、レベル2は7段の市松模様の配置でボールが速くなり、最上段は2回当てないと壊れません。ゲームオーバーとクリアの画面があります。
- **良い点：** 依頼した機能はすべて正常に動きます。4つの中で最も速く、最も安く済みました。
- **惜しい点：** 効果音やパーティクルといったゲームらしい演出がなく、ライフもハートではなく文字だけで表示されます。コードも198行で最も短くなりました。
- **向いている作業：** 動作だけ確認できればよい試作、簡単な修正。

### Sonnet 5.5 high：58秒、$0.30

- **作ったもの：** レベル2は空きマスが混じった7段の配置に2回当てないと壊れないブロックがあり、ボールが速くなってパドルが狭くなります。
- **良い点：** ブロックが壊れるとパーティクルが飛び、ハイスコア保存、レベルクリアボーナス、ウィンドウを離れると自動停止まで入っています。ライフは赤い点で表示されます。
- **惜しい点：** 2回当てないと壊れないブロックは、コード上は細い白枠と1回当たった後に薄くなる表現でしか区別されず、プレイ中は気づきにくくなっていました。タッチ操作はありません。
- **向いている作業：** 普段のコーディング、人に見せられる試作を安く作るとき。

## 実際に使ってみた感想

2つのゲームを実際に遊んだ感想と、普段ゲームを作りながら Sonnet を使ってきた経験です。測定値ではなく、体感です。

### Sonnet medium：物足りないが、機能は正常

とてもシンプルで、ゲームらしい演出もハートもないので物足りないですが、機能的には正常に動いている感じです。

画面を見るとすぐに違いがわかります。ブロックは壊れても何の演出もなく消え、ライフはハートではなく画面上部の「Lives: 3」という文字だけです。それでも、スコア、2レベル、ライフ3つ、キーボード・マウス操作と、依頼したものは1つも欠けていません。依頼書をチェックリストとして見れば合格ですが、ゲームとして見ると作り込みが足りません。「とりあえず動くか見たい」というときなら、これで十分です。

### Sonnet high：Opus high 並み、ただし1か所が惜しい

Opus 5.5 の high レベルの出来です。ゲームの演出ではパーティクルをうまく作っていました。ブロックが壊れるたびに破片が飛び、medium とは手応えがまったく違います。ハイスコア保存とレベルクリアボーナスまで入っていて、画面だけなら Opus high と並べても大きく見劣りしません。

ただ、2回当てないと壊れないブロックを、プレイヤーが気づけない作りにしていました。コードを見ると、このブロックは細い白枠だけで区別され、1回当たると少し薄くなる程度です。遊ぶ側からすると、ほかと同じに見えるブロックが1回当てても壊れないので、バグのように感じることもあります。機能は入れたのに、それをプレイヤーに見せる仕上げが抜けているわけです。

### 普段 Sonnet を使ってみると

細かく伝えても、思ったとおりにはなかなか実装されない感じがありました。機能を実装することはできますが、求めている細部まで持っていくには、何度も追加で依頼し続ける必要がある感じです。そのため、作っては直し、作っては直しを Opus よりも頻繁に繰り返していたと思います。

今回の Sonnet high の2回で壊れるブロックも、同じ形と見ることができます。「2回当てないと壊れないブロック」という機能は作れても、「プレイヤーが見てすぐわかるように」という細部は、もう一度依頼して初めて埋まるという具合です。

### 費用で見ると

今回の計測は1回の依頼で終わる小さなゲームだったので、この差は数字に出ていません。単純計算で、Sonnet high（$0.30）に同じ大きさの依頼をあと2回すると $0.90 になり、Opus high 1回（$0.75）より高くなります。実際の修正依頼は大きさがまちまちなので費用も変わりますが、直す回数が増えるほど Sonnet の安い単価の利点がすぐに小さくなる点は、あわせて考える必要があります。

## どの作業にどのモデルを使うか

![どの作業にどのモデルを使うか: 作業, おすすめ, 理由](/claude-sonnet-5-5-vs-opus-5-5-ja-2.jpg)

計測結果と実際に使った経験を合わせたおすすめです。

| 作業 | おすすめ | 理由 |
|---|---|---|
| 簡単な修正、動作確認用の試作 | Sonnet medium | 37秒、$0.25 で最も速く安い |
| 要件がシンプルなコーディング、新機能 | Sonnet high | Opus medium より46%安く、出来は Opus high に近い |
| 細部まで合わせる必要がある作業 | Opus medium〜high | Sonnet は細部まで詰めるのに修正依頼が多く必要だった |
| 完成度が大事な成果物 | Opus high | 最も高いが（$0.75）抜けが最も少ない |

- **注意：** 各1回、小さなゲーム1つで測った結果です。大きなプロジェクトや難しい問題では差が変わることがあります。
- **修正まで計算に入れましょう。** 1回で終わる作業なら Sonnet が確実に安いですが、望む結果まで何度も直すなら、その回数だけ費用と時間が増えます。

## 結論：シンプルな作業は Sonnet high、細部は Opus

- **最もコスパが良いのは Sonnet 5.5 high でした。** $0.30 で Opus medium（$0.56）より46%安く、出来は Opus high 並みでした。
- **Sonnet medium は速くて安いものの、物足りません。** 機能は正常ですが、ゲームらしい演出がありません。
- **細部まで合わせたいなら Opus です。** 計測でも Opus high の抜けが最も少なく、普段の使用でも Sonnet は望む細部まで持っていくのに修正がより多く必要でした。
