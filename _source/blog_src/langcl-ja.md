![Claude 日本語トークンは英語より65％多い？Opus 5.5実測](/claude-nihongo-token-ja.jpg)

Claude に日本語で頼むと、英語より多くのトークンを使うとよく言われます。ところが「どのくらい多いのか」は記事によって数字がばらばらです。3割増しという記事もあれば、100％近く多いという記事もあります。その多くは GPT のトークナイザーで測った数字をそのまま使っていて、Claude を使う人にそのまま当てはまるのかは分かりません。

そこで Claude Code を使って自分で測ってみました。同じ内容の文章と質問を日本語・英語・韓国語で用意し、Claude Opus 5.5 にまったく同じ条件で送って、入力トークン、出力トークン、実際の費用がそれぞれどれだけ違うかを比べました。測定日は2026年10月16日、料金は Anthropic の公式料金表（10月15日確認）を基準にしています。

この記事に出てくるトークン数と費用は、どれも Claude Code が応答と一緒に返した使用量（usage）と費用の値をそのまま写したものです。金額は1ドル＝158円で換算し、円を先に、ドルを括弧に書いています。

## どうやって測ったか

Claude Code は本来、起動するたびにシステムプロンプトとツールの説明書を約5万トークン読み込んでから動きます。この部分は英語で固定されているので、そのまま測ると言語による差がその下に埋もれてしまいます。そこでシステムプロンプトを「You are a helpful assistant.」の一行に差し替え、ツールもサイズの小さい Read だけを残しました。こうすると、毎回つく固定部分は約1,000トークンまで減ります。

| 項目 | 設定 |
|---|---|
| モデル | Claude Opus 5.5 |
| 思考の強さ（effort） | low（思考トークンが混ざらないように） |
| 実行ツール | Claude Code 2.1.295、ヘッドレスモード（-p） |
| システムプロンプト | 一行に差し替え |
| 測定日 | 2026年10月16日、実験ごとに各言語1回 |

比較に使った材料は2種類です。

- **同じ内容の文章1本：**「小さなチームが初めてのモバイルゲームを企画する方法」という文章を英語で570語ほど書き、同じ内容を日本語と韓国語に訳しました。空白を除いた文字数は、日本語版が1,553字、韓国語版が1,263字、英語版が2,506字です。
- **同じ質問5つ：** 中古ノートパソコンの選び方、早く眠る方法、普通預金と定期預金の違い、室内でバジルを育てる方法、新しい言語を毎日練習する方法。3つの言語で同じように聞き、「それぞれ一段落くらいで」答えてもらいました。

この材料で3つの実験をしました。読ませる（入力）、書かせる（出力）、そして普段使うように質問して答えをもらう場合です。

## 実験1：同じ文章を読ませたとき（入力トークン）

同じ文章を言語ごとに入れ、「OK とだけ答えて」と頼みました。答えが一語なので出力はほぼゼロで、入力トークンだけを比べられます。

| 言語 | 入力トークン（固定部分を除く） | 英語との差 |
|---|---:|---:|
| 英語 | 1,539 | 基準 |
| 日本語 | 2,083 | **＋35％** |
| 韓国語 | 2,435 | **＋58％** |

同じ内容を読ませるのに、日本語は英語より35％多くトークンを使いました。

ただし、この数字には言語に関係なく毎回つく部分が一部含まれています。Claude Code は、送った文章の前後に実行環境の情報などを付け足して送るためです。この部分を実験2の英語の結果（英語は約3.4文字で1トークン）から逆算すると、約600トークンと推定できます。これを除いて文章そのものだけを比べると、日本語は英語より約60％、韓国語は約99％多くなります。次の実験2の結果とほぼ同じ数字です。

## 実験2：同じ意味を書かせたとき（出力トークン）

![実験2：同じ意味を書かせたとき（出力トークン）: 言語, 出力トークン, 英語との差, 費用, かかった時間](/claude-japanese-token-translation-output-ja.jpg)

今度は逆に、同じ意味を各言語で書かせました。英語の原文を日本語と韓国語に翻訳させ、英語の結果は韓国語版を英語に翻訳させて得ました。3つとも最後まで漏れなく翻訳されています。

| 言語 | 出力トークン | 英語との差 | 費用 | かかった時間 |
|---|---:|---:|---:|---:|
| 英語 | 915 | 基準 | 約6.0円（$0.038） | 10秒 |
| 日本語 | 1,510 | **＋65％** | 約6.8円（$0.043） | 19秒 |
| 韓国語 | 1,850 | **＋102％** | 約7.8円（$0.050） | 23秒 |

**同じ意味を日本語で書かせると、出力トークンは英語より65％多くなりました。** 韓国語はさらに多く、102％増えました。

出力トークンが重要なのは料金のためです。Opus 5.5 は100万トークンあたり入力が4ドル、出力が20ドルで、出力の単価は入力より400％高く設定されています。日本語で答えを受け取るということは、いちばん高いトークンを英語より65％多く使うということです。

かかった時間も同じ方向に伸びました。モデルはトークンを一つずつ作り出すので、トークンが多いほど答えが終わるまで時間がかかります。日本語の翻訳は英語（10秒）より9秒長い19秒でした。

費用の差（＋13％）がトークンの差（＋65％）より小さいのは、入力側の事情です。翻訳する原文は入力として入りますが、日本語と韓国語の翻訳は英語の原文を、英語の翻訳は韓国語の原文を読みました。英語の結果を作るときに、より高くつく韓国語の原文を読んだため、差が一部縮まっています。

## 実験3：同じ質問を5つしたとき

実際に Claude を使う場面にいちばん近い実験です。同じ質問5つを各言語で聞き、その言語で答えてもらいました。

| 言語 | 出力トークン | 英語との差 | 費用 | 回答の文字数（空白除く） |
|---|---:|---:|---:|---:|
| 英語 | 1,371 | 基準 | 約5.3円（$0.034） | 3,355字 |
| 日本語 | 1,430 | ＋4％ | 約5.5円（$0.035） | 1,483字 |
| 韓国語 | 1,921 | **＋40％** | 約7.1円（$0.045） | 1,394字 |

この実験では、日本語は英語とほとんど差がありませんでした。理由は回答の長さです。日本語の回答は1,483字で、内容も英語の回答よりやや簡潔にまとまっていました。実験2で見たとおり、同じ意味を書かせれば日本語も65％多くなります。実際の使用では回答の長さがその都度変わるので、言語の差と同じくらい、回答の長さも費用を左右します。

文字数にも注目してください。日本語の回答は1,483字で、英語の回答（3,355字）の半分以下です。それでもトークン数はほぼ同じでした。日本語は1文字に込められる意味が多いので文字数は短くなりますが、トークンに直すとその分が打ち消されます。

韓国語は質問への回答でも40％、費用で35％多くかかりました。日本語より韓国語のほうが不利だったのは、3つの実験すべてで同じでした。

なお、この実験の回答は毎回少しずつ変わります。同じ質問でも、モデルがその時の判断で長めに答えれば日本語のトークンは増え、短く答えれば減ります。今回の日本語の回答が短めだったのもその一例で、もう一度聞けば英語との差が10％や20％になることも十分ありえます。言語そのものの差を知りたいときは実験2の数字を、普段の使い方での目安を知りたいときは実験3の数字を見るのがよいでしょう。どちらの場合も、日本語が英語より安くなることはありませんでした。韓国語も同じで、3つの実験のどれでも英語を下回ることはありませんでした。

## 1文字あたり何トークン？

![1文字あたり何トークン？: 言語, 1文字あたりのトークン（出力）, 1万字を出力する費用（Opus 5.5）](/claude-japanese-tokens-per-character-ja.jpg)

3つの実験の結果を文字数で割ると、言語ごとに1文字あたり何トークンになるかが分かります。

| 言語 | 1文字あたりのトークン（出力） | 1万字を出力する費用（Opus 5.5） |
|---|---:|---:|
| 英語 | 約0.3トークン（3.4文字で1トークン） | 約9円（$0.06） |
| 日本語 | 約0.9トークン | 約29円（$0.18） |
| 韓国語 | 約1.05トークン | 約33円（$0.21） |

日本語は**1文字がだいたい0.9トークン**と考えれば大きく外れません。よく言われる「日本語は1文字＝1〜1.5トークン」より少し少なめです。回答を1万字受け取ると、Opus 5.5 では出力だけで約29円です。ただし日本語1万字に入る内容は英語1万字よりずっと多いので、文字数ではなく同じ内容どうしで比べた実験2の＋65％が、実際の差に近い数字です。

自分のプロンプトが何トークンになるかは、文字を貼り付けるとトークン数と費用をすぐ表示する[トークンカウンター](/ja/)で測れます。

## なぜ日本語はトークンが多くなるのか

AI のモデルは文章を1文字ずつ読んでいるわけではありません。トークナイザーという仕組みが、文章をあらかじめ決めておいたかたまり（トークン）に切り分けます。このかたまりの一覧は、学習データによく出てくる文字の並びを集めて作られます。

学習データでは英語が圧倒的に多いので、英語はよく使う単語が前のスペースごと一つのトークンになることがよくあります。英語が約3.4文字で1トークンになったのはこのためです。

日本語は事情が違います。漢字・ひらがな・カタカナが混ざり、使われる文字の種類がとても多いうえ、コンピューターの中では多くの文字が1文字3バイトで保存されます。よく使う文字や短い言葉は一つのトークンにまとまりますが、そうでない文字はさらに細かく分けられます。今回の測定で日本語1文字が平均約0.9トークンになったのは、かたまりの一覧に入っている日本語の並びが英語ほど多くないということです。

韓国語も、子音と母音を組み合わせて作れる文字が1万1千以上あり、同じ問題を抱えています。今回の Claude の測定では、韓国語のほうが日本語より細かく分けられていました。どの言語をどれだけうまくまとめるかは会社やモデルごとに違い、同じ会社でもモデルが変われば変わることがあります。

## 自分で測る方法

Claude Code が入っていれば、今回と同じ方法で自分の文章を測れます。測りたい文章をファイルに保存して、ターミナルで次のように実行します。システムプロンプトを一行に差し替え、ツールを一つだけ残して、言語に関係ない固定トークンをできるだけ減らす設定です。

```
cat 原稿.txt | claude -p --system-prompt "You are a helpful assistant." --tools Read --output-format json
```

結果の JSON で見る場所は三つです。usage の中の output_tokens が回答に使った出力トークン、cache_creation_input_tokens と cache_read_input_tokens を足した値が入力トークン、total_cost_usd が API 料金に換算した費用です。同じ文章の日本語版と英語版を一度ずつ入れてみれば、自分の文章で言語の差がどれくらい出るのかがすぐに分かります。

Pro や Max のプランでログインしている場合、別にお金はかかりませんが、プランの使用量からその分が差し引かれます。1日に数回測るくらいなら上限にはほとんど影響しません。これまでの会話のトークンを日付やモデル別にまとめて見たいなら、[使用量アナライザー](/ja/claude-code-usage)に記録フォルダを入れてみてください。

## 日本語で特に差が広がる使い方

今回の実験は1回きりの短いやり取りでしたが、実際の使い方によっては日本語の不利さがもっと大きく効いてきます。気をつけたいのは次のような場面です。

- **長い会話を続けるとき。** チャットでは、新しいメッセージを送るたびにそれまでの会話全体がもう一度入力として送られます。会話が日本語なら、その全体が英語より約60％多いトークンで毎回読み直されます。1回ごとの差は小さくても、長い会話ほど積み重なります。
- **長い資料を読ませるとき。** 契約書、議事録、マニュアルのような長い日本語の資料を要約させると、入力トークンの差がそのまま費用に出ます。資料が英語でもある場合は、英語版を渡す方が安く済みます。
- **翻訳や記事作成のように、長い日本語を書かせるとき。** 実験2のとおり、同じ内容を日本語で書かせると出力トークンが65％増えます。出力は入力より単価が高いので、費用への影響がいちばん大きい使い方です。
- **プロジェクトの指示書を日本語で書くとき。** Claude のプロジェクト機能や Claude Code の CLAUDE.md のように、毎回読み込まれる指示書は、日本語で書くと毎回その分の入力トークンがかかります。長い指示書ほど英語で書く効果が大きくなります。

逆に、短い質問に短く答えてもらうような使い方なら、実験3のように差はほとんど目立ちません。日本語で使うこと自体を避ける必要はなく、長いものほど英語に寄せるという考え方で十分です。

## GPT や他の調査と比べると

![GPT や他の調査と比べると: 測定, 日本語, 韓国語](/claude-vs-gpt-japanese-token-ja.jpg)

TokenSave は9月に、同じ短いプロンプトを41言語に訳して GPT のトークナイザー（o200k_base）で数えたことがあります。そのときは日本語が英語より79％、韓国語が44％多いという結果でした。詳しい結果は[日本語プロンプトは英語で送るとトークン44％節約](/ja/blog/nihongo-tokens-gpt)にあります。

また、ITmedia の @IT が2026年5月に公開した独自調査では、OpenRouter 経由で各モデルの入力トークンを測っています。それによると日本語は英語に比べて、Claude Opus 4.7 で約39％、Opus 4.6・Sonnet 4.6・Haiku 4.5 で約95％、GPT-5.5 で約73％多いという結果でした。

| 測定 | 日本語 | 韓国語 |
|---|---:|---:|
| GPT（o200k_base、TokenSave 9月測定） | ＋79％ | ＋44％ |
| GPT-5.5（@IT 調査、入力） | ＋73％ | – |
| Claude Opus 4.6 ほか（@IT 調査、入力） | ＋95％ | – |
| Claude Opus 4.7（@IT 調査、入力） | ＋39％ | – |
| Claude Opus 5.5（今回、同じ意味の出力） | **＋65％** | **＋102％** |

材料の文章がそれぞれ違うので数字をそのまま並べて比べることはできませんが、二つのことが分かります。

一つ目は、**同じ Claude でもモデルの世代でトークナイザーが変わり、日本語の不利さが大きく変わる**ことです。@IT の調査では Opus 4.6 世代の＋95％から Opus 4.7 で＋39％まで下がっており、今回の Opus 5.5 は＋65％でした。古い記事の数字を今のモデルにそのまま当てはめるのは危険です。

二つ目は、**GPT では日本語が韓国語より不利だったのに、Claude Opus 5.5 では韓国語のほうが不利だった**ことです。今回の数字だけで見れば、日本語ユーザーにとっては Claude Opus 5.5 の方が GPT より日本語の差が少し小さいと言えます。

## 料金に直すとどのくらい違うか

実験3の質問5つの会話を、1日20回、1か月（30日）API で使うとします。実際に測った費用をそのまま掛けるとこうなります。

| 言語 | 1回の費用 | 1か月（600回） |
|---|---:|---:|
| 英語 | 約5.3円（$0.034） | 約3,200円（約$20） |
| 日本語 | 約5.5円（$0.035） | 約3,300円（約$21） |
| 韓国語 | 約7.1円（$0.045） | 約4,300円（約$27） |

質問への回答ではほとんど差が出ませんでしたが、これは日本語の回答が短めだったからです。翻訳や長い文章の作成のように、同じ内容を書かせる作業では実験2の＋65％に近づきます。たとえば英語なら月3,200円で済む翻訳作業は、日本語ではトークン換算で5,000円を超える計算になります。

Pro や Max のようなサブスクリプションはトークン単位で料金を払いません。ただし Anthropic は、使用上限が会話の長さや複雑さによって減ると案内しています。日本語の会話がより多くのトークンを使う分、上限も早く減る可能性が高いと考えられます。プランごとの上限は [Claude の料金プランまとめ](/ja/blog/claude-ryoukin-plan)にまとめています。

## 日本語のトークンを減らす方法

結果を見ると、減らせる場所ははっきりしています。

- **長い指示や資料は英語で入れましょう。** 毎回送るシステムプロンプトや参考資料は、英語で書くだけで入力トークンが大きく減ります。答えだけ日本語でほしいなら、最後に「Reply in Japanese.」を付ければ十分です。[トークンカウンター](/ja/)の 💸 トークン節約 ボタンを押すと、端末の中で英語に変換し、何％減ったかを表示します。
- **答えを必要以上に長くしないようにしましょう。** いちばん高いのは出力です。「3行で」「表だけで」のように長さを指定すれば、日本語の出力トークンを直接減らせます。
- **英語で読んでも困らない結果は英語で受け取りましょう。** コードの説明やログの分析のように、自分が読んで終わりの内容なら、英語の回答で出力トークンを4割ほど節約できます。
- **翻訳は最後に1回だけにしましょう。** 何段階もある作業なら途中は英語で進め、最終結果だけを日本語に訳させれば、高い日本語の出力を1回で済ませられます。

## よくある質問

**Claude は日本語のトークンを英語よりどのくらい多く使いますか？**
今回の Opus 5.5 の測定では、同じ意味を書かせたときの出力トークンが65％多く、同じ文章を読ませたときの入力トークンは固定部分を含めて35％、固定部分を除くと約60％多くなりました。

**日本語で使うと費用もそれだけ増えますか？**
トークンほどには増えません。今回の翻訳の実験では13％、質問への回答では4％でした。毎回つく固定のトークンや原文の入力が混ざるためです。長い文章を書かせる作業ほど、トークンの差に近づきます。

**GPT では79％と聞きましたが、なぜ違うのですか？**
会社ごと、モデルごとにトークナイザーが違うからです。今回の測定では、Claude Opus 5.5 は日本語1文字をおよそ0.9トークンとして扱いました。同じ Claude でも世代によって数字が大きく変わります。

**Claude Code でコーディングするときも同じくらい差が出ますか？**
コーディングエージェントでは、システムプロンプトやコードのように言語に関係ない部分が費用の大半を占めるので、差はずっと小さくなります。この記事の数字は文章を読み書きする作業の場合です。

**英語で質問して、答えだけ日本語でもらうと安くなりますか？**
入力側は安くなります。質問や資料を英語にすれば、その分の入力トークンは約60％少なくなります。ただし答えを日本語で受け取る限り、いちばん高い出力トークンは日本語のままです。短い質問なら効果は小さく、長い資料や指示書を英語にしたときに効果が大きくなります。

**プロンプトキャッシュを使えば差はなくなりますか？**
なくなりません。キャッシュから読み込むトークンは通常の入力より95％安くなりますが、日本語の資料はキャッシュの中でも英語より多いトークン数のままです。キャッシュで単価が下がっても、言語による割合の差はそのまま残ります。

**自分のプロンプトは何トークンですか？**
[トークンカウンター](/ja/)に貼り付ければ、モデルごとのトークン数と費用がすぐ分かります。計算はブラウザーの中だけで行い、どこにも送りません。

## まとめ

同じ内容を Claude Opus 5.5 に日本語・英語・韓国語で送ってみると、日本語は同じ意味を書かせたときの出力トークンが英語より65％多くなりました。韓国語はさらに多く、102％でした。文章を読ませたときも、日本語の入力トークンは35％、固定部分を除くと約60％多くなりました。一方、普段のように質問を5つした場合は、日本語の回答が短めだったため費用の差は4％にとどまりました。

GPT のトークナイザーで測った「日本語＋79％」より、Claude Opus 5.5 での差はやや小さく、GPT と違って Claude では韓国語のほうが不利でした。また、同じ Claude でもモデルの世代によって数字が大きく変わります。日本語で Claude をたくさん使うなら、長い指示は英語で書き、答えは必要な長さだけ受け取るのがいちばん確実な節約方法です。各実験は言語ごとに1回の測定なので、回答の長さによって結果は多少変わることがあります。
