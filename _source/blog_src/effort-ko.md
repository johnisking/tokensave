![클로드 오퍼스 5.5 effort 비교: low부터 max까지 실측](/claude-opus-5-5-effort-ko.jpg)

클로드 **오퍼스 5.5**에는 생각을 얼마나 깊게 할지 정하는 **effort** 설정이 low, medium, high, xhigh, max 다섯 단계로 있습니다. 단계가 올라갈수록 결과물이 좋아진다고 하지만, 시간과 비용이 얼마나 늘어나는지는 공식 자료에 숫자가 없습니다. 그래서 2026년 10월 9일, 같은 게임 제작 요청을 다섯 단계로 한 번씩 돌려 시간, 토큰, 비용, 결과물을 직접 비교했습니다. 가장 빠른 단계와 가장 느린 단계의 차이는 32초와 22분이었습니다. 단계마다 무엇이 달라졌는지, 어떤 작업에 어떤 단계를 쓰면 좋은지 직접 써 본 경험과 함께 정리했습니다.

## effort란

- **생각하는 양을 정하는 설정입니다.** 오퍼스 5.5는 생각(thinking)을 끌 수 없고, effort로 얼마나 깊게 생각할지 조절합니다. 생각한 토큰도 출력 토큰으로 요금이 붙습니다.
- **기본값은 medium입니다.** 오퍼스 5는 high가 기본이었는데, 오퍼스 5.5는 한 단계 낮은 medium이 기본입니다(Anthropic 문서 기준).
- **바꾸는 방법:** 클로드 코드에서는 `--effort` 옵션으로 low부터 max까지 고를 수 있고, API에서는 `effort` 값을 지정합니다.

## 실측 방법

- **모델:** 클로드 오퍼스 5.5, 클로드 코드(Windows PC)
- **요청(원문 그대로):** "Make a brick-breaker game that runs in the browser as a single file named index.html in the current folder. It needs 2 levels, a score display and 3 lives, and it must be playable with the keyboard and the mouse. Write the file and finish." 브라우저용 벽돌깨기 게임을 HTML 파일 하나로, 레벨 2개, 점수, 목숨 3개, 키보드·마우스 조작으로 만들어 달라는 내용입니다.
- **방법:** 같은 요청을 effort만 바꿔 다섯 번 실행했습니다. 단계마다 폴더를 따로 써서 서로 영향을 주지 않게 했습니다.
- **측정:** 토큰과 비용은 무료 도구 ccusage로, 시간은 시작·종료 시각으로 쟀습니다. 비용은 API 가격으로 환산한 값입니다.

## 결과물 비교: 다섯 게임 화면

![effort 5단계로 만든 벽돌깨기 게임 다섯 개의 실제 화면 비교](/claude-opus-5-5-effort-ko-5.jpg)

다섯 게임 모두 오류 없이 실행됐고, 레벨 2개, 점수, 목숨 3개, 키보드·마우스 조작이라는 요청은 모두 지켰습니다. 차이는 그 위에 얹은 기능과 꾸밈입니다.

| effort | 추가로 들어간 것 |
|---|---|
| low | 단색 벽돌, 가장 단순한 화면, 일시정지 없음 |
| medium | 무지개색 벽돌, 일시정지, 다시 시작 |
| high | + 파티클 효과, 최고 점수 저장 |
| xhigh | 파티클 효과, 더 다듬은 디자인 (최고 점수 저장은 없음) |
| max | + 효과음, 레벨 이름, 침략자 모양 레벨 2, 화면 흔들림, 승리 불꽃놀이 |

- **high부터는 스스로 검사하려고 했습니다.** high와 xhigh는 코드 문법 검사를, max는 게임을 자동으로 플레이해 보는 테스트를 시도했습니다. 셋 다 실행 승인이 필요해서 실제로 돌리지는 못했고, 코드를 다시 읽어 확인했다고 남겼습니다. low와 medium은 검사 없이 바로 끝냈습니다.
- **두 번 맞아야 깨지는 벽돌**은 요청하지 않았는데도 다섯 단계 모두 넣었습니다.

각 단계가 만든 게임을 직접 실행해 보고, 모델이 작업을 마치며 남긴 설명과 코드를 함께 확인했습니다.

### low: 32초, $0.48

![effort low로 만든 벽돌깨기 게임의 시작 화면과 플레이 화면](/claude-opus-5-5-effort-ko-11.jpg)

- **좋았던 점:** 요청한 기능은 빠짐없이 들어갔고, 패들의 어디에 맞느냐에 따라 공 각도가 바뀝니다. 32초 만에 끝났습니다.
- **아쉬운 점:** 검은 배경에 단색 벽돌이라 가장 밋밋합니다. 일시정지가 없고, 코드도 138줄로 가장 짧습니다.
- **이럴 때:** 기능만 빨리 확인하고 디자인은 나중에 다듬을 때.

### medium: 52초, $0.56 (기본값)

![effort medium으로 만든 벽돌깨기 게임의 시작 화면과 플레이 화면](/claude-opus-5-5-effort-ko-12.jpg)

- **들어간 것:** 레벨 1은 5×10 무지개 벽돌, 레벨 2는 빈칸이 있는 배치에 2~3번 맞아야 깨지는 벽돌이 섞여 있습니다. 남은 횟수가 벽돌에 표시되고, 맞을수록 흐려집니다.
- **좋았던 점:** 일시정지(P·Esc), 다시 시작(Enter), 창을 벗어나면 자동 일시정지까지 넣었습니다. 점수도 벽돌 내구도와 레벨에 따라 다르게 줍니다.
- **아쉬운 점:** 효과음이나 파티클 같은 꾸밈은 없습니다.
- **이럴 때:** 대부분의 작업. low보다 8센트 더 들고 완성도는 한 단계 위입니다.

### high: 1분 50초, $0.75

![effort high로 만든 벽돌깨기 게임의 시작 화면과 플레이 화면](/claude-opus-5-5-effort-ko-13.jpg)

- **들어간 것:** 레벨 2는 다이아몬드 모양에 2~3번 맞아야 깨지는 벽돌입니다. 벽돌이 깨질 때 파티클이 튑니다.

- **아쉬운 점:** 시간이 medium보다 112% 더 걸렸습니다(52초 → 1분 50초).
- **이럴 때:** 바로 보여 줄 프로토타입이나 완성도가 중요한 코딩. 비용은 medium보다 34%만 늘었습니다.

### xhigh: 4분 32초, $1.36

![effort xhigh로 만든 벽돌깨기 게임의 시작 화면과 플레이 화면](/claude-opus-5-5-effort-ko-14.jpg)

- **들어간 것:** 레벨 2는 다이아몬드 모양에 강철 벽돌 테두리가 있고, 강철 벽돌은 한 번 맞으면 금이 갑니다. 벽돌 색깔마다 점수가 10~50점으로 다릅니다.
- **좋았던 점:** 화면이 가장 정돈돼 보이고, 마우스와 키보드를 섞어 써도 마지막에 쓴 쪽으로 자연스럽게 움직입니다.
- **아쉬운 점:** high에 있던 최고 점수 저장과 터치 조작은 빠졌습니다. 비용은 medium보다 143% 많은데, high와 비교하면 기능이 더 늘지는 않았습니다.
- **이럴 때:** 이번 같은 작은 작업에는 과합니다. Anthropic 안내대로 오래 걸리는 큰 작업에 맞습니다.

### max: 22분 22초, $5.25

![effort max로 만든 벽돌깨기 게임의 시작 화면과 플레이 화면](/claude-opus-5-5-effort-ko-15.jpg)

- **들어간 것:** 레벨 이름("Rainbow Wall", "Space Invader"), 침략자 모양의 레벨 2(은색 벽돌 14개는 두 번 맞아야 깨짐), 레벨 2에서 더 좁아지는 패들이 있습니다.

- **아쉬운 점:** 다른 단계보다 압도적으로 오래 걸렸습니다. 자동 플레이 테스트를 시도하다 승인이 필요해 못 돌린 과정도 포함됐습니다.
- **이럴 때:** 품질이 가장 중요하고 시간·한도가 넉넉할 때, 또는 다른 단계로 안 풀리는 문제.

## 직접 써 본 경험: 평소엔 medium, 코딩은 high

저(재현)는 클로드 Max 20x 요금제로 게임을 만들면서 오퍼스 5.5를 씁니다. 측정값이 아니라 평소 쓰면서 느낀 내용입니다.

- **평소 설정:** effort를 자동(auto)으로 두고 씁니다. 평소에는 medium으로 돌아가고, 코딩 작업을 할 때는 high까지 올라갑니다.
- **low:** 답답한 느낌이 나서 몇 번 쓰고 안 썼습니다.
- **high:** 확실히 결과물이 좋다고 느꼈습니다.
- **xhigh·max:** 한 번 써 본 정도이고, 쓸 일이 거의 없어서 안 썼습니다.

실측과 비교하면, low는 속도는 가장 빨랐지만 결과물이 가장 단순했습니다. "답답하다"는 느낌은 속도보다 결과물 쪽이었던 셈입니다. high에서 결과물이 좋아진다는 느낌과 xhigh·max를 쓸 일이 없다는 느낌은 숫자와도 맞았습니다.

## Anthropic은 어떻게 안내하나

- **medium도 충분히 셉니다.** Anthropic 테스트에서 오퍼스 5.5 medium은 코딩과 지식 작업에서 오퍼스 5 high와 같거나 더 나았다고 합니다.
- **low도 코딩에서 medium에 가깝다고 합니다.** 비용은 훨씬 적다고 합니다. 다만 이번 실측에서는 결과물 차이가 눈에 띄었습니다.
- **xhigh와 max는 품질이 좋아지는 걸 확인한 작업에만 쓰라고 권합니다.**
- **중간에 effort를 바꾸면 캐시가 깨질 수 있습니다.** API에서는 메시지별로 바꾸는 방식을 쓰면 캐시가 유지됩니다.
- **독립 평가도 비슷합니다.** Artificial Analysis는 최고 설정의 오퍼스 5.5가 작업당 출력 토큰을 오퍼스 5보다 63% 더 썼다고 밝혔습니다(보도 기준).

## 어떤 작업에 어떤 effort를 쓸까

![어떤 작업에 어떤 effort를 쓸까: 작업, 추천 effort, 이유](/claude-opus-5-5-effort-effort-ko.jpg)

실측, 재현의 경험, Anthropic 안내를 합쳐 정리한 추천입니다.

| 작업 | 추천 effort | 이유 |
|---|---|---|
| 문구 수정, 파일 정리 같은 단순 작업 | low 또는 medium | 빠르고 싸지만 low는 결과가 단순 |
| 일반 코딩, 기능 추가 등 대부분의 일 | medium (기본) | 52초, $0.56에 쓸 만한 결과 |
| 게임·앱 프로토타입, 완성도가 필요한 코딩 | high | 비용 34% 증가로 결과물이 확실히 좋아짐 |
| 30분 넘게 도는 긴 작업, 큰 리팩터링 | xhigh | Anthropic 안내 기준 |
| 다른 단계로 안 풀리는 어려운 문제 | max | 시간·비용이 크게 늘어 꼭 필요할 때만 |

- **처음엔 medium으로 시작하세요.** 결과물이 아쉬운 작업만 high로 올리면 됩니다.
- **요금제 사용자는 한도 기준으로 보세요.** API 환산 비용이 클수록 Max·Pro 한도도 빨리 줄어듭니다. max 한 번이 medium 아홉 번보다 많이 썼습니다.
- **주의:** 단계마다 한 번씩, 비교적 작은 작업으로 잰 결과입니다. 큰 프로젝트에서는 차이가 다르게 나올 수 있습니다.

## 결론: 평소엔 medium, 잘 만들 땐 high

- **평소: medium.** 52초, $0.56에 쓸 만한 결과가 나옵니다.
- **완성도가 필요할 때: high.** 비용은 medium보다 34%만 늘고 결과물은 확실히 좋아졌습니다. 가성비가 가장 좋은 단계입니다.
- **xhigh: 작은 작업에는 비추천.** 비용은 medium보다 143% 많지만 high보다 기능이 늘지 않았습니다. 30분 넘게 도는 큰 작업에서나 의미가 있습니다.
- **max: 꼭 필요할 때만.** 결과물은 가장 화려하지만 22분, $5.25가 들었습니다.
- **low: 비추천.** medium보다 8센트 아끼려다 결과물만 단순해집니다.

## 자주 묻는 질문

**오퍼스 5.5의 기본 effort는 무엇인가요?**
medium입니다. 오퍼스 5는 high가 기본이었습니다. API에서 effort를 지정하지 않으면 오퍼스 5.5는 medium으로 동작합니다.

**max로 하면 무조건 더 좋은가요?**
이번 실측에서는 기능과 꾸밈이 가장 많았지만, 시간은 22분, 비용은 $5.25로 medium(52초, $0.56)과 차이가 컸습니다. 간단한 작업에는 과합니다.

**low로 쓰면 많이 아낄 수 있나요?**
이번 실측에서 low는 medium보다 14% 쌌을 뿐입니다. 결과물이 단순해지는 걸 감안하면 medium이 낫습니다.
